# Scene board

After a prop is ready, the center stage shows the Lux3D GLB on a booth floor grid, with a `generated by Lux3D` badge, face budget, and orbit camera.

## Sub-features

- `board-mount` loads the proxied GLB into Three.js.
- `board-badge` shows `generated by Lux3D` and the task id.
- `board-orbit` lets the user drag to orbit (OrbitControls).
- `board-floor` sits the mesh on y = 0 (world up is +y).

## How to get to it (user POV)

- Complete Generate a prop until status is `ready`.
- Look at the center panel labeled Scene board.

## Driving it with verify-sceneops

Preconditions:

- A task is `ready` in this session (from generate-prop).
- `job-task-id` matches the API task.

- **See the canvas.** `getByTestId('scene-canvas')` exists and has non-zero width and height.
- **See the badge.** `getByTestId('lux3d-badge')` has text `generated by Lux3D`.
- **See face budget.** `getByTestId('asset-faces')` is visible.
- **Mesh bytes.** `GET /api/mesh/<taskId>` is HTTP 200, `Content-Type` includes `model/gltf-binary` or `octet-stream`, body starts with `glTF`.
- **Proof.** Screenshot `docs/proof/03-scene-board.png` showing the mesh, the badge, and the SceneOps wordmark.

## Gotchas

- WebGL can fail in a headless browser without `--use-gl=angle` / GPU flags. The helper launches Chrome with `--use-gl=angle --enable-webgl`. If the canvas is 0×0, that is a harness issue; still require the GLB magic bytes from `/api/mesh`.
- Do not screenshot an empty grid and call it a model. The mesh must be visually present or the run must say the canvas could not composite and point at mesh bytes plus task.json.
- World up is +y. The floor is the XZ plane. Do not treat a mesh floating far above the grid as success if the loader failed to sit it.
