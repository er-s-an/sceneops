# Verify SceneOps

SceneOps is a browser ops board. A user types a short booth/field brief, the Node server calls Aholo Lux3D (`G1` or `G1-Turbo`), the client polls until a GLB exists, Three.js mounts it, and an ops checklist (placement, collision, print/export) attaches. Without generate+poll+GLB the product is invalid. Never accept a placeholder mesh.

This skill is for the next agent. Follow Launch, Doctor, Drive, Evidence, Cleanup in that order. Prefer the helper CLI over ad-hoc clicks.

Repo root: the directory that contains `package.json` and `.cursor/skills/verify-sceneops/`.

Default local URL: `http://127.0.0.1:5173` (Vite) with API on `http://127.0.0.1:8787` proxied as `/api`. Production-style single process: `http://127.0.0.1:8787` after `npm run build && npm start`.

## Launch

From the repo root:

```bash
test -f .env.local || { echo 'missing .env.local with AHOLO_API_KEY'; exit 1; }
npm install
npm run dev
```

`npm run dev` starts the API on port 8787 and Vite on port 5173. Ready when:

- `curl -sS http://127.0.0.1:8787/api/health` returns JSON with `"ok": true` and `"hasKey": true`
- `curl -sS -o /dev/null -w '%{http_code}' http://127.0.0.1:5173` is `200`

A one-shot helper that waits for both:

```bash
node .cursor/skills/verify-sceneops/scripts/verify.mjs launch
```

It writes the API PID and Vite PID to `.cache/verify/pids.json`. Do not start a second pair on the same ports. If 5173 or 8787 is already owned by this repo's previous run, reuse it after `doctor`. If owned by something else, stop and say so.

Empty data dir: `.cache/verify/` and `.cache/meshes/` may be created. They are verification scratch, not product state.

Teardown is Cleanup below.

## Doctor

Read-only. Run before every drive if anything looks off:

```bash
node .cursor/skills/verify-sceneops/scripts/verify.mjs doctor
```

Pass means all of:

- API process answers `GET /api/health`
- `hasKey` is true (the key itself is never printed)
- `region` is `com`
- Vite (or the combined server) returns HTTP 200 for `/`
- The HTML title contains `SceneOps` and a `#root` mount node. Test ids live in the React tree, so doctor does not look for them in the empty shell. Happy-path does.

Fail means do not drive. Print the failing check and the HTTP body of `/api/health` with any key-shaped strings redacted.

## Drive

Harness: Playwright against Chromium (`channel: "chrome"` when `/usr/bin/google-chrome` exists). Helper:

```bash
node .cursor/skills/verify-sceneops/scripts/verify.mjs happy-path
```

Stable handles (use these, not CSS position):

| Handle | Role |
| --- | --- |
| `brief-prompt` | textarea, ops brief |
| `brief-version` | select, `G1` or `G1-Turbo` |
| `brief-style` | select, Lux3D style |
| `brief-sample-stanchion` | button, loads the stanchion sample |
| `brief-generate` | button, starts Lux3D |
| `job-status` | live region, one of `idle`, `submitting`, `polling`, `ready`, `failed` |
| `job-task-id` | visible Lux3D task id once assigned |
| `scene-board` | the 3D stage |
| `scene-canvas` | WebGL canvas |
| `lux3d-badge` | text `generated by Lux3D` |
| `asset-faces` | face budget |
| `checklist-placement` | checkbox |
| `checklist-collision` | checkbox |
| `checklist-print-export` | checkbox |
| `prop-download` | link or button, GLB download |

Happy path (this is the proof the contest requires):

1. Open `/`.
2. Click `brief-sample-stanchion` or fill `brief-prompt` with the stanchion sample from `src/lib/samples.ts`.
3. Set `brief-version` to `G1-Turbo`.
4. Click `brief-generate`. It disables while a job is in flight.
5. Wait until `job-status` is `polling` and `job-task-id` is a non-empty integer. That proves create, not a fake id.
6. Wait until `job-status` is `ready` (Lux3D status 3). Timeout 12 minutes. Poll `/api/tasks/<id>` as well; `glbUrl` must be a real URL, not a fixture path.
7. Assert `lux3d-badge` is visible, `scene-canvas` exists, and `/api/mesh/<taskId>` returns a body whose first four bytes are `glTF` (`0x67 0x6c 0x54 0x46`).
8. Toggle the three checklist items. They persist for that task id.

Do not stub Lux3D. Do not load `public/placeholder.glb`. If the API key is missing or credits are zero, fail the run and say what is needed.

Image-to-3D is a second mapped feature. Drive it only after the text-to-3D happy path is green.

## Evidence

Put proof in `artifacts/verify/<run-id>/` (gitignored) and copy the three contest screenshots to `docs/proof/` (committed):

| File | What it must show |
| --- | --- |
| `docs/proof/01-brief.png` | Brief filled, Generate enabled, English UI |
| `docs/proof/02-polling.png` | `job-status` polling and a numeric `job-task-id` |
| `docs/proof/03-scene-board.png` | Canvas with a generated mesh, badge `generated by Lux3D` |
| `artifacts/verify/<run-id>/health.json` | `/api/health` body |
| `artifacts/verify/<run-id>/task.json` | `/api/tasks/<id>` body with `status: 3` and a `glbUrl` |
| `artifacts/verify/<run-id>/mesh.head` | first 16 bytes of the proxied GLB as hex |
| `artifacts/verify/<run-id>/cli.log` | full helper stdout |

Proof standards:

- Exercise the UI path, not only `curl` create. `curl` is extra, not a substitute.
- Capture the action (generate click) and the resulting state (ready + mesh bytes).
- Side effect: a new Lux3D task id that `GET /global/lux3d/v1/generate/task/get?taskid=` would recognize. The helper records the id, never the API key.
- Mocks are forbidden for generate, poll, and GLB. Health may hide the key.

Cleanup must not delete `docs/proof/` or `artifacts/verify/`.

## Cleanup

```bash
node .cursor/skills/verify-sceneops/scripts/verify.mjs cleanup
```

Kills only the PIDs in `.cache/verify/pids.json`. Never `pkill -f vite` or `pkill -f node`. Leaves `artifacts/verify/` and `docs/proof/` in place. Leaves `.env.local` in place.

## Helpers

All helpers are executable via `node <path>`.

```bash
node .cursor/skills/verify-sceneops/scripts/verify.mjs doctor
node .cursor/skills/verify-sceneops/scripts/verify.mjs launch
node .cursor/skills/verify-sceneops/scripts/verify.mjs happy-path
node .cursor/skills/verify-sceneops/scripts/verify.mjs cleanup
```

`happy-path` launches if doctor fails because nothing is listening, then drives, then leaves the server up (so screenshots can be retaken). Call `cleanup` when the session is done.

Equivalent npm script: `npm run verify` runs `doctor` then `happy-path`.

Keep `/maintain-verification-skill` in mind after UI copy or selector changes.
